# Plate — 设计文档

**日期：** 2026-05-27
**作者：** Carl Guo
**状态：** 设计已确认，待实现

---

## 1. 定位

单人自用的 iOS 原生 app，把**菜谱、每日饮食、训练**三件事整合在一个闭环里。

**动机：** 现有 fitness app 要么只记卡路里、要么只记训练，没有一个能把"我有哪些菜谱 → 今天做什么 → 吃了多少 → 配合训练强度"串起来。Plate 的核心差异化是这个闭环本身，以及对**力量训练 + 不固定球类运动**的现实排程支持。

**目标用户：** 仅作者本人。未来再考虑是否泛化。

**名字寓意：** *Plate* 一词双关 — 餐盘（食物）+ 杠铃片（重量）。

---

## 2. 范围

### MVP 必做（v1.0）

- 食材库（内置 50–80 种中式常见食材 + 自定义）
- 菜谱 CRUD：食材（克数或个数）+ 做法 + 自动营养计算 + 自由标签 + 时间戳笔记
- 每日饮食记录：引用菜谱（支持小数份数）+ 散装食材
- 训练默认模板 + 每周排程生成器 + 球类冲突检测 + 手动调整
- 力量训练记录（动作 / 组 / 重量 / 次数）
- 球类/有氧记录（时长 + 主观强度高/中/低）
- 今日 Tab（饮食 + 训练整合视图）
- 回顾 Tab（基础周/月趋势图）

### 明确推迟（v2+）

- HealthKit / Apple Watch 集成
- 智能营养建议（如"今天练腿，多吃 XX g 蛋白"）
- 外食记录
- 多用户 / 账号系统
- 复杂分析图表
- 食材条码扫描
- 菜谱分享 / 导入

## 3. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Swift | 现代 iOS 标准 |
| UI | SwiftUI | 单人开发效率最高 |
| 持久化 | SwiftData (iOS 17+) | 比 Core Data 简单，单用户本地够用 |
| 架构 | MVVM | 标准、清晰 |
| 同步 | SwiftData + CloudKit（开启） | 静默 iCloud 备份，换机不丢数据 |
| 后端 | 无 | 全本地，离线可用 |

## 4. 数据模型

### `Ingredient`（食材库）
```
id
name                  // "鸡蛋"、"鸡胸肉"
caloriesPer100g
proteinPer100g
carbsPer100g
fatPer100g
defaultUnitGrams?     // 如 1 个鸡蛋 = 50g；nil 表示只按克记
isBuiltIn             // 区分预设和自添加
```

### `Recipe`（菜谱）
```
id, name, steps（富文本）
ingredients: [RecipeIngredient]
servings              // 一锅几份
tags: [String]        // 自由定义，多选
notes: [RecipeNote]   // 每条带时间戳
// 计算属性: totalCalories, perServingProtein, ...
```

`RecipeIngredient` = `Ingredient` + (**克数** 或 **个数**) — 二选一，可在同一菜谱内混用。

### `MealEntry`（饮食记录）
```
id, date, mealType    // 早/午/晚/加餐
items: [MealItem]
```

`MealItem` 两种来源任选其一：
- 引用 `Recipe` + 份数（支持 0.5 / 1.5 等小数）
- 引用 `Ingredient` + 数量（按克或按个）

营养数据**实时计算**，不冗余存储。

### `WeeklyPlan`（训练周计划）
```
weekStartDate
days: [DayPlan]       // 7 天
```

`DayPlan`：当天力量训练类型（推/拉/腿/休息/自定义）+ 已知运动安排（球类等）+ 冲突标记。

### `WorkoutEntry`（训练记录）
用 enum 区分两种子类型：
- **力量：** 动作列表，每个动作有多组 (重量, 次数)
- **球类/有氧：** 运动类型 + 时长（分钟）+ 强度（高/中/低）+ 笔记

动作名维护用户字典，方便追踪同动作的长期进步曲线。

## 5. 界面结构

### 底部 Tab Bar — 4 个 tab

#### Tab 1 · 今日
每天打开就看这个。垂直滚动，三个 section：
- **训练：** 今天计划 / 完成状态 / 一键打开记录
- **饮食：** 今日记录的餐 + 累计营养 + 进度条；底部"＋ 加一餐"
- **快捷入口：** 常吃的菜谱、再来一份昨天的午餐

#### Tab 2 · 菜谱
- 顶部搜索 + 标签筛选
- 列表/网格切换
- 详情页：食材清单（带营养占比）+ 做法 + 笔记时间线 + "记录到今日饮食"按钮
- 新建：分步表单（基本信息 → 食材 → 做法 → 标签）

#### Tab 3 · 训练
默认本周视图（横向 7 天）：
- 每天显示计划 + 完成状态 + 冲突提示
- "本周排程"按钮 → 基于默认模板 + 本周球类安排生成日程，自动避冲突
- 点某天 → 力量记录（动作/组/重/次）或球类记录（时长/强度）
- 子页：默认模板设置、动作库

#### Tab 4 · 回顾
- 周 / 月切换
- 热量摄入 vs 训练强度叠图
- 蛋白质摄入趋势
- 力量核心动作进步曲线（如卧推最大重量）

## 6. 关键设计原则

1. **零摩擦优先** — 日常操作 3 次点击内完成
2. **称量只发生一次** — 建菜谱时称一次，之后按"份数"引用
3. **不强制完美** — 份数允许小数、训练计划随时改、无连胜惩罚
4. **本地优先** — 全部离线可用，iCloud 仅做静默备份

---

## 7. 训练排程逻辑（核心差异化）

现有 app 都假设训练日程固定。Plate 必须处理"周中临时打球，腿日要躲开"。

**方案：** 默认周模板 + 每周生成 + 实时调整

1. 用户先定义**默认周模板**（如：周一推、周三拉、周五腿、周末休）
2. 每周开始：
   - 输入本周已知运动安排（周四篮球、周日跑步）
   - App 基于模板生成本周排程，**自动避开冲突**（如把腿日从周五挪到周二）
   - 用户可手动覆盖任意一天
3. 周中可随时拖动调整，app 实时重新检查冲突并**提示但不强制**

**冲突规则（MVP）：**
- 腿日不应在大量跑动的球类运动前 24h 内
- 同肌群两次训练间隔 ≥ 48h

## 8. 开发分期

业余时间，单人开发。

| 阶段 | 内容 | 估时 |
|---|---|---|
| P0 | 项目脚手架、SwiftData schema、内置食材种子数据 | ~1 周 |
| P1 | 菜谱模块（CRUD + 笔记 + 营养计算） | ~2 周 |
| P2 | 饮食模块（每日记录 + 营养汇总） | ~1.5 周 |
| P3 | 训练模块（模板 + 周排程 + 力量/球类记录） | ~2.5 周 |
| P4 | 今日 Tab 整合 + 回顾 Tab 基础图表 | ~1 周 |
| P5 | 抛光、bug 修、自用试跑 2 周 | ~3 周 |

**总计：约 2–3 个月业余时间到能自用。**
